# Лабораторная работа 2

## Тема

Потоки, процессы и асинхронность в Python.

## Суть задания

Нужно было показать разные способы параллельного и асинхронного выполнения задач. В работе реализованы два типа задач: вычисление суммы большого диапазона чисел и параллельный парсинг веб-страниц.

## Задача 1. Сумма чисел

Требовалось посчитать сумму чисел от `1` до `10_000_000_000_000` тремя способами:

- через `threading`;
- через `multiprocessing`;
- через `asyncio`.

Реализованные файлы:

| Подход | Файл | Механизм |
| --- | --- | --- |
| `threading` | `scripts/lab2/sum_threading.py` | Диапазон делится на части, каждая часть считается в отдельном потоке. |
| `multiprocessing` | `scripts/lab2/sum_multiprocessing.py` | Диапазон делится на части, каждая часть считается отдельным процессом. |
| `asyncio` | `scripts/lab2/sum_async.py` | Диапазон делится на асинхронные задачи, запускаемые через `asyncio.gather`. |

Чтобы программа запускалась за разумное время, сумма каждого диапазона считается по формуле арифметической прогрессии, а не циклом по 10 триллионам чисел.

## Задача 2. Параллельный парсинг веб-страниц

Требовалось реализовать парсинг веб-страниц тремя способами:

- через `threading`;
- через `multiprocessing`;
- через `asyncio` и `aiohttp`.

Реализованные файлы:

| Подход | Файл | Механизм |
| --- | --- | --- |
| `threading` | `scripts/lab2/parse_threading.py` | URL делятся между потоками. |
| `multiprocessing` | `scripts/lab2/parse_multiprocessing.py` | URL делятся между процессами. |
| `asyncio` + `aiohttp` | `scripts/lab2/parse_async.py` | URL загружаются конкурентно через `aiohttp`. |

Каждая программа загружает HTML-страницы, достает заголовок страницы и сохраняет результат в PostgreSQL.

## Таблица для результатов парсинга

Для хранения результатов добавлена таблица `parsed_pages`.

| Поле | Назначение |
| --- | --- |
| `url` | Адрес страницы. |
| `title` | Заголовок страницы. |
| `status_code` | HTTP-статус ответа. |
| `content_length` | Размер HTML. |
| `parser_type` | Подход, которым выполнен парсинг. |
| `error` | Текст ошибки, если страницу не удалось загрузить. |
| `created_at` | Дата и время сохранения результата. |

## Запуск

Перед запуском программ нужно поднять PostgreSQL и применить миграции:

```bash
source .venv/bin/activate
docker compose up -d postgres redis
alembic upgrade head
```

Запуск задачи с суммой:

```bash
python -m scripts.lab2.sum_threading
python -m scripts.lab2.sum_multiprocessing
python -m scripts.lab2.sum_async
```

Запуск парсинга:

```bash
python -m scripts.lab2.parse_threading
python -m scripts.lab2.parse_multiprocessing
python -m scripts.lab2.parse_async
```

## Сравнение подходов

| Подход | Особенности |
| --- | --- |
| `threading` | Удобен для сетевых задач, потому что потоки могут ожидать ответы от разных сайтов. |
| `multiprocessing` | Лучше подходит для CPU-bound задач, потому что процессы обходят ограничение GIL. |
| `asyncio` | Хорош для большого количества I/O-bound операций, например HTTP-запросов. |

Асинхронный парсер обычно работает быстрее для сетевых задач, потому что программа не блокируется на ожидании одного сайта, а одновременно ожидает ответы от нескольких сайтов.

## Вывод

В лабораторной работе были реализованы три модели конкурентного выполнения в Python. На примере суммы и парсинга показано, что выбор подхода зависит от типа задачи: для вычислений лучше подходят процессы, а для сетевых запросов - асинхронность или потоки.
